what did the pod receive?

The screen-stream analogue of twitter-debug: the browser turns a live screen into a stream of JPEG frames and POSTs each one to this pod's sink; the sink stores the trace and echoes it back. You compare what you sent against what the pod received, frame by frame — bytes, luma, latency, HTTP outcome. Try it below, then copy the three files.

open source: code · README · server.ts (the sink)

the pipeline · three steps
  1. capture — getDisplayMedia → downsample to a target width → per-frame luma → JPEG, entirely in the browser (capture() in this page's source).
  2. post — each frame goes direct browser → pod sink, tagged with your oauth3 identity (window.oauth3.signIn; oauth3 is never in the frame data path).
  3. echo — the sink stores the last 60 frames + metadata and serves them back, so the receive side is inspectable next to the send side.

desktop-only: getDisplayMedia isn't implemented on mobile browsers. A screen-picker prompt appears on Start.

use this as a template

The whole app is three files in one directory — webhost-apps/screenshare-debug. Copy it, point deploy.sh at your pod, done.

  • server.ts — the sink + trace store (under 100 lines, deno, zero deps)
  • public/index.html — the capture client (this page)
  • deploy.sh — tarball → POST /_api/projects on a tee-daemon
deploy: bash deploy.sh # no secrets needed
