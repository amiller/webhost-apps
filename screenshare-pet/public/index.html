a pet that watches your screen

A small animated pet floats in an always-on-top window while you work and reacts to signals derived from your screen — cheap pixel math nearly always (is it still? where is the activity? did the whole scene just change?), with rare, budgeted escalation to OCR or a visual model. The whole thesis as a toy: rich-feeling awareness without a model in the loop. Frames never leave your browser unless you turn on the dev-only mirror.

headless harness — drive the pet without capture

The pet logic is fully testable with no screen-share and no network. The state machine is a pure function of the latest signal + elapsed time, exposed on window.__pet:

window.__pet.feed({ changedPct: 0.04, class: "local", hot: { x: 0.2, y: 0.3, w: 0.1, h: 0.1 }, _t: 1234567890000 }) window.__pet.mood() // → "attentive" (gaze tracks the hot region) window.__pet.runSynthetic() // detector + state machine over a fake moving rect window.__pet.forceTrigger("vlm") // respects budget; reports "not configured" when off window.__pet.framePosts() // [] with the mirror toggle off

how it works
  1. capture — getDisplayMedia → downsample to a target width (default 240px — we want signal math, not pixels). The capture pipeline is ported from screenshare-debug.
  2. detect — the downsampled frame is tiled into a 10×6 grid; per-tile mean luma is differenced against the previous frame. Output: {changedPct, hot, class} where class is still / local (a few tiles, e.g. typing) / scene (a global flip, e.g. alt-tab).
  3. react — a small state machine (the table at the top of the script) maps the signal stream to a mood: still → sleepy → nap; local → attentive with gaze tracking the hot region; scene → startled; sustained motion → mesmerized; long idle → wanders off.
  4. escalate (rare) — on a scene change, at most every few minutes, the pet may grab one hi-res keyframe for OCR (vendored tesseract.js, local) or a one-line VLM caption (VLM_URL), and comment via a speech bubble. A counter shows model calls vs frames processed — the point is how rarely it fires.

no frame ever leaves the browser unless you tick debug: mirror to sink (a dev-only loopback echo on this same app's own server — no consent, no credential, no storage). The on-page counter asserts it: mirror off ⇒ frame POSTs stays 0.
