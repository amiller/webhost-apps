# Bullet 3 — consent-line PNG capture (rework pass, 2026-08-05)

The earlier run's "screenshot times out on every page" diagnosis was WRONG. The envoy bridge
`screenshot` tool works on real http(s) URLs; it only fails on about:blank / data: pages, where the
extension has no host permission. The bridge log showed the real error for an about:blank attempt:

  {"id":"h-msgkz70l","success":false,
   "error":"Cannot access contents url \"\". Extension manifest must request permission to access this host."}

and a screenshot of a REAL url the same minute returned a valid PNG data-URL:
  {"id":"f3","success":true,"result":"data:image/png;base64,iVBORw0KGgoAAAANSUhEUgAA..."}

So the capture was re-run against the real dashboard URL and succeeded on the first try.

## What this proves / what it does NOT
- PROVES (bullet 3): the consent line names the account the enclave will act as —
  "twitter-debug will act as twitter account 111" — rendered by the real dashboard code from the
  real agent's `account:"111"` (the ACCOUNT env via TWITTER_ACCOUNT).
- Does NOT re-prove the connected write path: this capture booted no OAuth3 token, so the lockpill
  reads "🔒 read-only". The connected path ("🔓 writes on", account 111's jar loaded) is already
  proven end-to-end in bullet1-connect-account.txt and bullet3-consent-evaluate.txt. The consent-line
  text is identical in either state (it depends only on status.account, not on connection).
